# Routing Guide

Use this file to choose the smallest useful lane before writing.

## Lane Table

| Lane | Use when the user asks about | Default output |
|---|---|---|
| concept-lane | a term, topic, software, workflow, or beginner question | plain-language definition, analogy, examples, takeaway |
| source-lane | a file, image, diagram, screenshot, transcript, paper, or long article | source inventory, fact/inference split, caveats |
| writing-lane | a public article, WeChat/公众号 draft, short explainer, title, or outline | reader-first outline and polished copy |
| review-lane | privacy, originality, uncertainty, public release, or final check | redaction list, claim boundaries, safe wording |

## Route Selection Rules

- If the user asks "what is this", start with concept-lane.
- If the user provides a source, start with source-lane even when the final output is an article.
- If the user gives a topic and target article format, start with writing-lane.
- If the user mentions public posting, publication, GitHub, screenshots, private files, or copied material, include review-lane.
- If the task mixes learning and writing, use a two-step answer: "learn just enough" then "write for the audience".

## Minimal Clarifying Questions

Ask only when the answer changes the artifact:

- Target audience: beginner, professional, patient/public, students, or researchers?
- Output format: summary, article, Word document, slide outline, checklist, or script?
- Length: short, 800-1000 words, 1500 words, or no limit?
- Source status: public source, private draft, screenshot, paper, or internal material?
- Publishing destination: private study note, public article, GitHub, or social media?

When a safe default exists, state the assumption and continue.
