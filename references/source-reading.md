# Source Reading Guide

Use this file for documents, screenshots, diagrams, videos, transcripts, papers, and other source material.

## Source Inventory

Before writing, identify:

- source type: paper, Word file, PDF, image, screenshot, video, transcript, web page, code, or draft
- visible or extractable claims
- missing context
- whether the source is public or private
- whether current verification is needed

## Fact Boundary

Separate information into:

- **directly supported**: visible in the source or present in provided text
- **reasonable inference**: likely interpretation, stated as inference
- **needs verification**: tool behavior, versions, prices, public status, citations, laws, or claims not visible in the source
- **unsafe to publish**: private details, credentials, internal names, or personal identifiers

## Image and Workflow Sources

For screenshots, posters, and diagrams:

- Explain the purpose of the image in original words.
- Reconstruct the workflow by meaning, not by copying labels line by line.
- Do not reproduce command lists unless the user asks for a runnable tutorial.
- Say whether it appears to be a personal workflow, a product stack, a method map, or a standard process.

## Papers and Technical Documents

For papers and technical documents:

- Extract problem, method, evidence, result, limitation, and significance.
- Distinguish computation, experiment, review, opinion, and speculation.
- Do not overstate novelty, causality, or clinical meaning.
- Convert the technical summary into public language only after the core claims are clear.
