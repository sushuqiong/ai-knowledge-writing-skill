# Seven-Step Public Writing Workflow

## 1. Frame

Capture topic, intended reader, purpose, length range, tone, format, source
status, and freshness requirement. Defaults for an underspecified explainer are:
beginner audience, neutral and lively tone, short sections, no invented sources,
and plain text unless an artifact was requested.

## 2. Read

Inventory every supplied source. For an image, distinguish visible text and
objects from interpretation. For a document, identify its genre, date, author or
publisher when available, and missing methodological detail. Do not assume that
an attachment is correct or complete.

## 3. Verify

Use [evidence-boundaries.md](evidence-boundaries.md). Current prices, product
features, policies, guidance, medical claims, and release dates require a fresh
check when feasible. Prefer primary sources and record the access date.

## 4. Structure

Build a reader-first outline around the requested question. A useful explainer
shape is: relatable opening, plain definition, why it matters, how it works,
what the reader can do, limitations, and one-sentence takeaway. Vary the shape
when the topic calls for comparison, chronology, or a list.

## 5. Draft

Use short paragraphs and concrete verbs. Define a technical term at first use.
Avoid inflated promises, fake quotations, stacked rhetorical questions, and
unsupported certainty. Keep the article within the requested count rather than
padding it with generic background.

## 6. Deliver

Return text in the requested format. If DOCX is requested, render it locally,
reopen it with a structured reader, verify the count scope and metadata, and
inspect it with an office application when available.

## 7. Audit

Check required concepts, article length, source coverage, originality, privacy,
links, file integrity, and any high-stakes disclaimer. Report what was verified
and what remains uncertain.
